01 — THE PROBLEM

AI writes code in seconds.
Then the entropy sets in.

Point a raw model at real software and it sprints — then drifts. Without structure, every productive session quietly accumulates the failure modes that make the next one worse.

Context rot

The window fills with logs, dead ends, and stale instructions. Quality degrades exactly when the task gets hard.

Decisions trapped in chat

The "why" lives in a transcript that vanishes on /clear. The next session re-litigates settled choices.

The re-discovery tax

Every session re-derives how the codebase is wired — paying the same exploration cost again and again.

Reviews by vibes

Confident, plausible, wrong. Hallucinated APIs and silent failures slip through because nothing reviews them systematically.

Amnesia

The bug you fixed last week, the gotcha you mapped — gone. Lessons don't survive the session that learned them.

One-size pipeline

A typo fix and a migration get the same ceremony — so people skip the process entirely, right when it matters most.

02 — THE SHIFT

Typed artifacts beat chat.

The core move: stop steering through conversation. Capture intent as files — PRDs, architecture, stories, ADRs — generated from templates. Artifacts are the handoff medium between agents, and they survive context resets.

06 — THE SPLIT

Plan heavy. Edit cheap.

The architect→editor split mirrors how senior engineers actually work: a high-reasoning model designs against a story; a fast model applies the diff. Right model, right job — better results, lower cost.

07 — QUALITY GATES

Nothing ships on a vibe.

Verification is structural, not optional. Reviews fan out in parallel; completion claims require fresh evidence; disciplines are enforced as loadable skills.

Parallel review fan-out

/review runs code, security, and performance auditors at once, then aggregates by severity — not by reviewer. Anti-slop guardrails kill confident-but-wrong findings.

Verification gate

/ship won't claim "done" without running the command and reading the output. Stub scan, real test results, every acceptance criterion checked.

Disciplines as skills

test-driven-development and systematic-debugging load on trigger — RED→GREEN→REFACTOR, and no fix without a reproduction and a named root cause.

08 — THE FLYWHEEL

Engineering that compounds.

The killer feature. Every solved problem is captured as a typed learning and a linked note in an Obsidian memory vault. Before the next plan, the learnings-researcher recalls what's relevant — so the team gets sharper with every task instead of starting from zero.

09 — THE ADVANTAGE

Why teams reach for it.

It's not more AI. It's AI with the operating discipline of a good engineering org — encoded once, applied every session.

Survives /clear

State lives in git-tracked artifacts and a memory vault — not in a fragile transcript. Reset anytime; pick up cold.

Compounds over time

The learning flywheel means task N+1 is informed by task N. Your AI team accrues institutional memory.

Right-sized, always

A strict knowledge-verification chain and reviewer guardrails catch invented APIs and silent failures before they merge.
